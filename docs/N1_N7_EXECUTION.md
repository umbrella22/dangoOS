# N1–N7 实现与集中验收

更新：2026-10-24。功能范围以 [HANDOFF.md](HANDOFF.md) 的 N1–N7 为准。

## 分支与审查方式

`main` 保留当前基线 `80e362ebcccaed80c29fcb7c09ec4ebf5541f171`。
持续开发和修复使用 `codex/n1-n7-integration`；每完成一项，创建一个指向该阶段完成
提交的本地审查分支，并记录固定的 base / head 提交。

阶段分支是当时版本的快照。后续发现问题时，在集成分支增加带阶段编号的修复提交，
记录在本表后续修复栏。审查以固定提交范围看每项变化，真机验收使用最新集成镜像，
这样前置修复不需要重复同步到所有历史快照。需要复现某个旧阶段时，单独检出该快照；
其测试记录仅适用于当时的源代码和镜像。

本地提交和阶段分支用于审查与恢复，不推送远程。每项实现由同一个 Sol 6.1 编码代理
完成，主代理负责架构约束、独立审查、集成和验收；总并发上限为 2。

## 实施顺序与依赖

实施顺序为 **N1 → N2 → N3 → N7 → N4 → N5 → N6**，编号保留需求原义。

| 阶段 | 内容 | 依赖与审查重点 |
| --- | --- | --- |
| N1 | 六个 Lua 硬件模块 | 固件任务保有外设所有权；快照、受限请求、资源释放；Lua 马达输出差异继续跟踪 |
| N2 | AI / BOOT 与关机 | 复用 N1 button 语义；上电按住、去抖、单击 / 双击 / 长按；Sleep 帧交付后关机 |

| N7 | 卸载与应用数据隔离 | 提前建立每 VM 数据根，供 N4 / N5 多 VM 使用；稳定应用 id、断电恢复、USB / UI 共用执行路径 |
| N4 | Lua 情绪引擎 | 使用 N1/N2 事件、N3 渲染和 N7 VM 上下文；后台 VM、原生兜底、错误 / 超时、热重载保留旧版 |

最终镜像体积和设备分区，安排在其他代码集成之后。

## 每阶段交付与验收

每项保存独立接口 / 实现文档、相关主机测试、固件构建结果、固件大小与 SHA-256，以及
待测试动作和通过条件。阶段审查通过后记录 head，再开始下一项。最终运行集成检查并
