# N1–N7 实现与集中验收

更新：2026-10-23。功能范围以 [HANDOFF.md](HANDOFF.md) 的 N1–N7 为准。

## 分支与审查方式

`main` 保留当前基线 `80e362ebcccaed80c29fcb7c09ec4ebf5541f171`。
持续开发和修复使用 `codex/n1-n7-integration`；每完成一项，创建一个指向该阶段完成
提交的本地审查分支，并记录固定的 base / head 提交。

阶段分支是当时版本的快照。后续发现问题时，在集成分支增加带阶段编号的修复提交，
记录在本表后续修复栏。审查以固定提交范围看每项变化，真机验收使用最新集成镜像，
这样前置修复不需要重复同步到所有历史快照。需要复现某个旧阶段时，单独检出该快照；
其测试记录仅适用于当时的源代码和镜像。

本地提交和阶段分支用于审查与恢复，不推送远程。每项实现由同一个 Sol 6.1 编码代理
完成，主代理负责架构约束、独立审查、集成和验收；总并发上限为 2。

## 实施顺序与依赖

实施顺序为 **N1 → N2 → N3 → N7 → N4 → N5 → N6**，编号保留需求原义。

| 阶段 | 内容 | 依赖与审查重点 |
| --- | --- | --- |
| N1 | 六个 Lua 硬件模块 | 固件任务保有外设所有权；快照、受限请求、资源释放；马达实物失败继续跟踪 |
| N2 | AI / BOOT 与关机 | 复用 N1 button 语义；上电按住、去抖、单击 / 双击 / 长按；Sleep 帧交付后关机 |
| N3 | 可推送皮肤包 | 格式版本和完整校验、原子切换、坏包兜底、重启保留；资源体积提供给 N6 决策 |
| N7 | 卸载与应用数据隔离 | 提前建立每 VM 数据根，供 N4 / N5 多 VM 使用；稳定应用 id、断电恢复、USB / UI 共用执行路径 |
| N4 | Lua 情绪引擎 | 使用 N1/N2 事件、N3 渲染和 N7 VM 上下文；后台 VM、原生兜底、错误 / 超时、热重载保留旧版 |
| N5 | 原版 album_app | 对照实际官方脚本实现 lvgl / image / thread；UI 独占 LVGL、worker 状态隔离、原版脚本与图像验证 |
| N6 | A/B 分区与 USB OTA | 以完整固件体积验槽；旧布局兼容、只写非运行槽、完整校验后激活、回滚和迁移 / 恢复工具 |

N7 已将数据根改为每 VM 独立上下文，默认根只在创建时复制。后续常驻大脑和
相册 worker 使用这一上下文隔离能力。N6 同时涉及资源布局、
最终镜像体积和设备分区，安排在其他代码集成之后。

完整收据为 `target/n6-acceptance-20261023/receipt.json`。最终默认 BIN 为 **3045376 字节**，
3 MiB 槽剩 **100352 字节**；包含 N1–N7 全部实现，兼容已明确识别的旧表和新 A/B 表。
SHA-256 为 `17b1949ef90c1cd72de4f8fe7d6b1330e91c1d1de9390ed6c693883c0f9b6ab4`。
正常与故障注入镜像分别命名；当前 Cargo target ELF 已恢复正常默认版本。

最终检查覆盖 360 项 Rust 测试（255 S31、53 Lua、10 FS、42 驱动）、46 项 Python 测试、
预览、默认及 panic feature 构建和 713 个 C 符号的 ROM 冲突检查。独立 N6 探针覆盖
39 个新旧镜像语料、十次全镜像交替更新、六类拒绝与 39 个 I/O 故障场景。
这些检查均为主机 / 构建证据。N1 的既有真机观察只适用于 N1 镜像；马达手持无震动
仍为失败，后续全部阶段实物验证尚未运行。

## 每阶段交付与验收

每项保存独立接口 / 实现文档、相关主机测试、固件构建结果、固件大小与 SHA-256，以及
待测试动作和通过条件。阶段审查通过后记录 head，再开始下一项。最终运行集成检查并
提供统一真机清单，优先查影响后续测试的启动、存储和输入，再逐项验证功能。

N6 的实现包含分区表生成、备份要求、校验、迁移与恢复命令。实物重划分区需要保留
`0x0..0x20000` 备份并在集中验收时明确授权，来源是 [HANDOFF.md 的红线](HANDOFF.md#红线)。
代码准备与主机验证可以先完成；实际擦写分区表和旧 `/data` 的结果必须单独记录。
迁移前的 ROM 刷机只写 main_app `0x210000`；迁移后正常 OTA 写入非运行槽及 otadata，
不碰 bootloader 或出厂 vibe_mode。N1–N5/N7 历史镜像不支持新的 data 定位，迁移后不能
刷回做阶段复现。因此先完成其他阶段的现场检查，再做 N6 备份、迁移与 OTA 验收。
