# v21-probe：渲染与触摸延迟分阶段测量

适用硬件：ESP32-S31-Korvo-1 + SUB3 800×480 RGB LCD、GT1151 触摸。

该诊断构建基于 v20，增加计时和工作量统计。启动标识为 `v21-probe`，并输出 CPU 频率。温度历史、绘制、缓存发布和触摸事件的行为保持 v20 的实现。

每次心跳增加一条 `[perf]`：

| 字段 | 含义 |
| --- | --- |
| `n` | 本统计窗口的渲染帧数 |
| `px` / `full` | 每帧平均脏像素数 / 整屏重绘次数 |
| `isr_us` | 渲染期间 LCD ISR 像素搬运的平均累计耗时 |
| `touch_us` | 本窗口最大触摸轮询间隔 / 最大读取耗时 |
| `phase_us` | 每帧平均准备与布局 / 脏区计算 / 清底 / 场景绘制耗时 |
| `text_us` | 场景中的文字绘制耗时 |
| `path_us` | 场景中的路径绘制 / 其中蒙版生成耗时 |
| `rect_us` | 场景中的矩形绘制耗时 |
| `mask_px` / `paths` | 每帧平均蒙版像素数 / 本窗口路径调用次数 |

所有耗时单位为微秒。文字、路径和矩形包含在场景绘制中，蒙版包含在路径绘制中；中断搬运也包含在相应阶段的墙上时间中，不能重复相加。

应用镜像烧录地址为 `0x10000`。启动后静置 40 秒，再依次点击 25、100、AUTO，采集空闲与操作期间各几组心跳和 `[perf]`，同时保留启动版本和 CPU 频率行。

原心跳的触摸最大值仍是自启动累计值；`[perf] touch_us` 每个统计窗口重新累计。诊断输出使用 UART，会额外占用少量主循环时间，阶段计时不包含这些串口打印。

该构建用于区分布局与脏区、光栅化、PSRAM 访问和 LCD 中断的成本，不构成触摸延迟已解决或静态红边已修复的结论。
