# v15 版本说明（PCLK 采样边沿修正 + 全量硬件诊断）

## 本版改了什么（重点：找到了闪烁的真根因）

**PCLK 采样边沿接反了 —— 这是从第一版就存在的根因，与 DMA/缓冲/交换无关。**

证据链：
- 官方 BSP 明确要求 `BSP_LCD_RGB_PCLK_NEG = true`（面板在 PCLK **下降沿**采样数据）
- IDF 的映射是确定的：`lcd_ll_enable_pclk_active_neg(dev, en)` 直接写 `dev->lcd_clock.lcd_ck_out_edge = en`
  → `active_neg = true` 即 **out_edge = 1**
- S31 寄存器定义：`out_edge`: "1 = LCD_PCLK 在数据周期前半为高；0 = 后半为低"
  → out_edge=1 的数据有效窗口落在 PCLK 高电平期间，面板在下降沿采样，与 active_neg=true 吻合
- 而 esp-hal 里 `lcd_ck_out_edge = (phase == Phase::ShiftHigh)`
- **我们此前一直传 `Phase::ShiftLow` → out_edge = 0，与 BSP 要求正好相反**

后果：数据在错误的边沿跳变，面板在电平过渡态采样 → 逐像素噪点 / 整屏闪烁。
这解释了为什么 v13→v14 加大搬运窗口、调整帧交换时机都毫无改善：那些都没碰到真正的原因。

本版取 `Phase::ShiftHigh`（= out_edge=1 = pclk_active_neg=true）。

## 顺便加的全量硬件诊断（不依赖软件模型）

新增两组硬件真相仪表，用来验证修复并保证以后不再靠猜：

1. **面板侧**（LCD_CAM 帧结束中断）：面板实际刷新率 + 帧周长实测
   —— 时序发生器跑在 PCLK 上，与数据供不供得上无关，所以它测的是真实扫描速度
2. **DMA 侧**：两次 out_eof 的真实间隔、一帧内收到的 out_eof 个数（期望**恰好 48**）、
   消隐期空档数（期望 = 帧数）、LCD 欠载中断计数、LCD 读到无效数据的计数

外加启动时打印：LCD 时钟寄存器实际值（源选择/分频值）+ 前几条 out_eof 描述符地址样本。

## 验收时请看

- **屏幕闪烁是否消失**（本版核心目标）
- 串口心跳：
  - `[面板] 帧=xx(35.4Hz)` —— 面板真实刷新率应≈35.4Hz
  - `帧周长avg/max=28200us` —— 应≈28200µs
  - `[DMA] 块/帧avg(min/max)=48(48/48)` —— 必须恰好 48；小于 48 说明丢中断事件
  - `间隔avg/max≈515/4000us` —— 515µs 是单块扫描时间，4000µs 是消隐期空档
  - `空档` —— 应≈帧数
  - `欠载=0(+0) 无效读+0` —— DMA 侧没有饿到面板
- 启动时那几行 `LCD 时钟读回` 与 `out_eof 描述符地址样本` 也请一并回传

## 本版未改（保持单一变量）

- 弹跳缓冲仍是 4 块、帧交换时机仍是 row=0（v14 的改动保留，它们本身没问题）
- 风扇斜坡步长、触摸轮询与渲染同线程（体验项，等闪烁结论后再动）
