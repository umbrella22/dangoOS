# 狐狸团子渲染管线：从 PNG 原稿到 AMOLED

这份文档按数据流走一遍狐狸团子是怎么上屏的，每一步讲“做了什么”和“为什么这样做”，
最后是踩过的坑和调试方法。它对应的代码是：

| 阶段 | 位置 | 运行在 |
| --- | --- | --- |
| 素材管线 | `assets/fox-dango/tools/*.py` | 开发机（Python，一次性） |
| 打包产物 | `crates/mosaico-s31/src/fox/data.rs`、`crates/mosaico-s31/src/assets/fox.bin` | 编译期 `include_bytes!` |
| 动画 | `src/fox/animate.rs`、`src/fox/entrance.rs` | 设备 / host |
| 渲染 | `src/fox/scene.rs`、`src/fox/render.rs` | 设备 / host |
| 双缓冲 | `src/ui/canvas_pool.rs`、`src/ui/fox_widget.rs` | 设备 / host |
| 上屏 | `src/tasks/plane.rs`、`src/drivers/display.rs` | 仅设备 |

```text
1254x1254 PNG 原稿 (20 个表情 + 局部变体)
   │  fox_build.py   统一裁切缩放 → 保边平滑 → 128 色调色板 → 去噪点
   │  fox_parts.py   变体与底图做差 → 补丁 / 精灵 / manifest.json
   │  fox_pack.py    RGB565 查回索引 → 行 RLE → fox.bin + data.rs
   ▼
FoxAnimator(表情, 时间) ──▶ Scene { pose, under 层, warp, over 层 }
   ▼
FoxRenderer：索引缓冲合成 (签名缓存) → 最近邻形变 + 调色板查表 → 叠 over 层
   ▼
CanvasPool 两个 352x336 RGB565 槽位 (渲染下一帧时上一帧在传)
   ▼
plane 任务 (中断执行器)：等 TE → 11 块 32 行 QSPI DMA → CO5300 (原点 64,88)
```

## 1. 素材管线（开发机）

目标：把 20 张高清插画变成设备上又小又快的数据，而且不失真。

### 1.1 统一几何

`fox_build.geometry()` 取 20 个表情内容区域的并集，算出**同一个**裁切框和缩放比，
所有表情都用它贴到 352x336 画布上，底部对齐，顶部留 24 px 给跳跃和弹出。

为什么：如果每张图各自裁切居中，切换表情时身体会跳一下。统一几何让“同一只狐狸”
在每张图上的位置和大小完全一致，表情切换只换脸。

### 1.2 保边平滑 `smooth_flat`

原稿有细微的纸纹噪声。直接量化会让噪声变成斑点。做法：

- 先算每个像素邻域的亮度极差（`MaxFilter - MinFilter`）。
- 极差小于 `edge`（18）的地方是平坦区（皮肤、毛），用高斯模糊（半径 1.5）的值替换；
  在 `edge/2` 到 `edge` 之间平滑过渡；线稿和高光处极差大，保持原样。
- **极差窗口必须覆盖模糊核的支撑范围**（`win = 2*ceil(2r)+1`）。窗口小于模糊核时，
  高光旁边的像素会被判成“平坦”然后把高光模糊进来，眼睛高光周围出现一圈光晕。

### 1.3 调色板 `palette_565`

全部表情拼成一张大图，统一量化成 128 色：

- 用**中位切分**（按像素数量切）而不是“最大覆盖”：大面积的浅色皮肤能分到约 20 级
  渐变，而不是 3 级色带。`kmeans=3` 再精修切分框。
- 设备最终显示的是 RGB565。很多 8 位调色板条目在 565 下会落到同一个值，白白浪费了
  约四分之一的调色板。所以先转 565 去重，不够 128 个就多切几个框再来，最后保留使用
  最多的 128 个**互不相同的 565 颜色**。
- 调色板 128 色意味着每像素 1 字节索引（实际最多 255 个，255 留作透明）。

### 1.4 去噪点 `despeckle`

皮肤恰好落在两个相近的调色板颜色之间时，源图噪声会让单个像素在两者之间来回跳，
屏上就是白色斑点。做法：

- 每个像素看 5x5 邻域，统计每个调色板索引的票数。
- **只有和本像素颜色相近**（RGB 距离 ≤ 24）的索引才能投票。线稿、真边缘涉及的是
  远色，不参与投票，所以不会被抹掉。
- 某个相近色的票数比自己多出 6 票以上就换成它；迭代 3 轮。

### 1.5 拆部件 `fox_parts.py`

动画需要的不是 20 张静图，而是“底图 + 可替换的小块”：

- 变体图（如 `idle__blink`）和底图做差，连通的差异区域合并成矩形，就是**补丁**
  （眨眼、嘴型、耳朵、视线、螺旋眼）。补丁不透明、位置固定。
- 符号（Zzz、汗滴、火花、问号）从底图里抠出来变成带 alpha 的**精灵**，可以单独位移、
  缩放和淡出；底图上它们的位置用周围颜色补上。
- `manifest.json` 记录每个部件的位置、类型和动画提示。

### 1.6 打包 `fox_pack.py`

- 每个 RGB565 值查回调色板索引（因为前面保证了图片是“565 精确”的，所以不会有未命中）。
- 每行做 RLE：`(count 1..=255, index)` 字节对，一行的 count 之和等于图宽，
  索引 255 表示透明。
- 产出 `src/assets/fox.bin`（所有图的 RLE 拼在一起）和 `src/fox/data.rs`（调色板 + 每张图的偏移、尺寸、位置）。
  两者都入库，所以编译固件不需要 Python。

## 2. 动画（每帧，设备上）

`FoxAnimator` 把“表情 + 经过时间”变成一个 `Scene`，**不分配内存**：

- `pose`：用哪张底图（`FoxPose::from(Expression)`）。
- `under`：在形变**之前**盖到底图上的层（补丁、贴身精灵），最多 24 层，定长数组。
- `warp`：整只狐狸的形变（`sx, sy, dx, dy`），锚点是**底部中心**，所以呼吸、
  压扁时脚不离地。
- `over`：形变**之后**才盖的层（Zzz、汗滴），它们自己飘，不跟着身体压扁。

时序（呼吸周期、眨眼间隔、pop 的阻尼振荡等）与 `fox_anim.py` 一致，Python 版用来离线出
视频审片，Rust 版是同一套参数。目标平台没有 libm，`fox/math.rs` 提供多项式 sin/cos、
`(1+x/16)^-16` 近似 exp、快速反平方根。

入场动画 `entrance::pose(ms)` 是纯函数：ease-in 下落、落地阻尼压扁、一次小跳。它也只
输出偏移和缩放，交给 `warp` 处理，因为上屏窗口位置是固定的。

## 3. 渲染（每帧，设备上）

`FoxRenderer::render(scene, out)` 分三步：

### 3.1 合成索引缓冲（大部分帧跳过）

把底图和 `under` 层解码进一个 352x336 的 **u8 索引缓冲**（不是 RGB565）。

- 用索引而不是颜色：缓冲只有一半大，解码就是 `fill(index)`，透明判断是比一个字节。
- **签名缓存**：对 `pose + under 层列表`（每层的图、位置、缩放、淡入值）算一个 FNV 哈希。
  和上一帧一样就直接复用索引缓冲。只呼吸不眨眼的帧（绝大多数）完全不需要重新解码。

### 3.2 形变 + 调色板查表（每帧）

- 没有形变时直接逐像素 `PALETTE[idx]`。
- 有形变时是**最近邻反向映射**：每个输出像素算回源坐标取索引。x 方向的映射每帧只算一次
  放进查找表 `xlut`，每行只算一个 `sy`。内层循环只有一次表查和一次调色板查。
- 不做双线性：像素画风格下最近邻不会糊边，而且快得多。

### 3.3 叠 over 层

over 层的位置用 `warp.forward` 算出形变后的落点，然后按原尺寸直接盖到 RGB565 输出上。

**淡入淡出不用 alpha**，用 4x4 Bayer 有序抖动：`fade`（0..16）决定 16 个格子里亮几个。
这样不需要读回背景做混合，也不会引入调色板之外的颜色。

## 4. 双缓冲与上屏（仅设备）

### 4.1 两槽 canvas pool

`CanvasPool` 有两个 352x336 的 RGB565 槽位，每个槽位的状态是 `FREE → WRITING → READY → READING`，
每次状态转换都是一次 compare-exchange：

- 渲染端拿 `WriteLease`（唯一能拿到 `&mut [u16]` 的途径），上传端拿 `ReadLease`（唯一能拿到
  `&[u16]` 的途径），所以渲染和 DMA 不可能同时碰同一块内存。这是用类型保证的，不是注释里的约定。
- 渲染第 N+1 帧时第 N 帧在传。上传比渲染慢时，没被取走的旧 READY 帧会被回收，屏上永远是最新一帧。

### 4.2 plane 任务

- 跑在**中断执行器**（FROM_CPU_INTR1，优先级 2）上：每块 DMA 一完成就能立刻发下一块，
  不用等线程模式的渲染让出 CPU。
- 每帧先等面板的 TE（撕裂效应）上升沿，最多等 30 ms，超时就直接传，避免画面撕裂又不会卡死。
- 画布按 32 行一块（`MAX_CHUNK_ROWS`）打包成大端字节，通过 QSPI DMA 写入 GRAM。336 行 = 11 块。
- 窗口 x 坐标和宽度必须是 **4 像素对齐**（CO5300 的要求），352 和 64 都满足。
- 画布在面板上的位置：水平居中，垂直方向比居中再低 16 px（`FOX_DROP_PX`），原点 (64, 88)。

## 5. 数据

| 指标 | 数值 |
| --- | --- |
| 调色板 | 128 色 RGB565 |
| 画布 | 352x336，约 236 KB / 帧 |
| host 渲染（开发机） | Idle 约 103 µs / 帧，Panic（带符号层）约 133 µs / 帧 |
| 设备渲染 `ras` | p50 约 10.4 ms；带符号层时约 15 ms |
| 设备上传 `tx` | 13–14 ms（11 块） |
| 帧率 | 18–20 fps（动画节拍 50 ms） |
| 丢帧 | 0 |
| 对比：原 grok-ball 矢量光栅 | 240x240 画布约 19.4 ms / 帧 |

画布面积是原来的 2 倍，渲染时间反而减半：矢量光栅每帧要算多边形覆盖率，精灵渲染只是查表。

## 6. 踩过的坑

1. **numpy 整数回绕**：uint8 数组相减、平方或左移 16 位都会静默回绕（例如把 RGB 拼成
   24 位键做 565 去重、算两色距离）。这类计算前先 `astype(np.int32)`。
2. **量化斑点**：原稿的细噪声 + 两个相近调色板色 = 脸上的白点。单靠加颜色数解决不了，
   需要量化前保边平滑 + 量化后同色系投票去噪。
3. **高光光晕**：保边平滑的极差窗口比模糊核小，高光旁的像素被当成平坦区，把高光模糊出去一圈。
   窗口必须覆盖模糊核。
4. **565 重复条目**：8 位调色板在 RGB565 下大量重合，有效颜色只剩约四分之三。要在 565 空间去重。
5. **方形画布假设**：原来的小球是 240x240，代码里有用 `WIDTH` 代替 `HEIGHT`、`w == h`
   分支、`CANVAS_SIZE` 这类假设。换成 352x336 后位置算错。现在宽高分开命名。
6. **4 像素对齐**：窗口不对齐时面板直接显示错位，没有错误返回。断言写在 `write_canvas_async` 里。
7. **串口监视无输出**：控制台是 USB-OTG CDC-ACM，不是 USB-Serial-JTAG。`espflash monitor`
   有时什么都不打印，直接用 pyserial 打开 `/dev/cu.usbmodemmosaico_s31_r11` 读就行。

## 7. 调试方法

- **host 网格图**：渲染器是纯 Rust、`no_std + alloc`，能在电脑上跑。把 20 个表情或一段动画的
  多帧渲染进一张大图（PPM），一眼就能看出错位、斑点、裁切。`examples/preview.rs` 和
  `examples/splash_preview.rs` 就是这个思路。
- **和原稿对比**：把设备数据（调色板 + RLE 解码）还原的图和 1254 原稿缩小版并排放大，
  斑点和色带问题都是这样定位的。
- **串口遥测**：UI 任务每秒打一行 `anim= ras= drop= fox= q=`，plane 任务打
  `frame= chunks= transfer=`。改性能先看这些数，而不是凭肉眼判断。
- **固定参数先离线**：动画参数先在 `fox_anim.py` 里调好出视频，确认后再搬到 Rust，
  设备上只做验证。
