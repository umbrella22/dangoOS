## 100% 震动的现场证据

原实现把名义 100% 限制为 199 tick 高、1 tick 低，实际编码为 99.5%。
同一实验镜像、同一次启动的交错对照中，旧编码 3 次 160ms 均无触感，
新 100H/100H 编码 3 次均有，90% 与 99% 对照稳定。随后新编码的 60/80ms 单次、
Error 原 3×60ms/40ms gap、Panic 原 3×80ms/60ms gap 均正常，间隔和结束能停振。
原始数据、矛盾历史观察与正式固件状态见 [现场记录](../N1_HAPTIC_LIVE_20261023.md)。

图 14 支持高电平使 MOSFET 导通的驱动模型。它没有证明旧编码失败的电气原因，
也没有规定 RMT continuous 模式行为。RMT RAM / FSM / INT_RAW 的含义仍以锁定的
HAL、PAC 和芯片技术参考资料核对；触感、寄存器快照、逻辑分析仪波形分别记录。
End 标志或 RAM 读地址为零不独立证明输出早停。

## 下载后自动回应用

资料 PDF 32（印刷 29）明确：芯片复位时 USB 会短暂断开，监视器需重新连接；
出厂 BSP 的自动下载配置不代表本项目已经实现同一功能。

本机已验证两条不同路径：

1. 运行时 `reboot`：命令发出后 USB 在 ACK 前断开，后续启动日志记录 CoreSw 与
   默认 Lua 大脑正常启动。串口会话退出 2 不单独判定重启失败。
2. 下载 stub：完整应用读回与引导区比对成功后，先启动有界运行口采集器，再在原
   stub 句柄执行一次 esptool 5.6 `watchdog-reset`，随后关闭旧串口。设备自动回到
   应用，日志 `32-waveform-autoboot.log` 记录正常启动，无人工 RESET。

esptool 的 `no-reset` 返回 ROM，不等同于回到应用；`watchdog-reset` 的证据来自
工具源码与实物链路，PDF 没有给出该命令。刷写成功、复位命令返回、应用启动成功
分别留存证据。写入范围继续受 [HANDOFF 红线](../HANDOFF.md#红线) 约束。

## 换槽与电源验收

交互板安装说明 PDF 67（印刷 64）要求关机或关闭对外 3.3V/5V 后插接。
后续实物换槽采用先关机、换槽、POWER 开机的顺序；GPIO60 同时影响屏幕，当前
固件没有独立子板断电入口。既有带电拔插结果仅保留为当时的软件恢复观察，
不作为该指南允许热插拔的依据。

N2 的关机请求来源为 AI 软件手势，重新上电测试使用独立 POWER 物理键。
USB 供电和电池供电分别记录，关机电流必须实测，不能用屏幕变黑代替。

2026-10-23 出现右槽灯带在 AI 关机和 ROM 下载模式下仍亮的报告。应用关机路径
需要主动发送完整黑帧，并等 RMT 结束与 WS2812 锁存间隔后再请求断电；RMT
idle-low、清空软件颜色和进入 Sleep 均不独立证明六颗灯已经熄灭。物理复位进入
ROM 不经过应用清理，启动清灯也只能在应用运行后执行。保留颜色是待验证解释，
未测电源轨和数据波形时不能据此宣布电气根因。

2026-10-24 再核对 PDF 第 34 页（印刷 31，图 10）：GPIO60/VCC_PW 连接 Q5
P-MOS 栅极，R51 为至 MCU_3V3 的 100kΩ 上拉。该电路图不能单独证明实际 RESET
或 ROM 期间的 GPIO 电平与输出轨电压。第 33 页框图也显示板载器件分布于多个
电源域，GPIO60 不代表全部外设断电。

源码存在正常复位后的清灯延迟：原 RMT task 在屏幕、触摸和模块初始化后才启动。
`c86811b` 提前该 task，在 USB 启动后、LCD 初始化前最多等待 100 ms，取得完整
Startup 黑帧与锁存回执；超时仍继续启动并记录缺口。组合 `c8e4f00d` 启动日志已
确认黑帧先于触摸初始化。应用入口之前、RESET 保持及 ROM 停留均不在这个软件
清灯承诺内，GPIO57／GPIO60 电气行为未修改；物理时点和复位电源轨仍须实测。

同镜像后续物理 RESET 采集记录到 USB 消失／返回和启动黑帧成功。操作者确认主页
恢复后灯已熄灭且点按有效；没有确认灯早于主页熄灭。这项观察只支持重启后残灯
清除，不证明全部外设断电。原始证据和临时页清理见 [N4 现场记录](../N4_BRAIN_LIVE_20261024.md)。
