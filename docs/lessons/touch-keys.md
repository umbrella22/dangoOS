## 1. 背景知识：S31 的电容触摸怎么工作

- 触摸焊盘就是一块铜皮，接在芯片的触摸通道上。芯片反复给它充电、放电，数一段时间里
  振荡了多少次，得到一个计数（raw data）。手指靠近会让焊盘对地电容变大，计数随之改变。
- S31 的触摸外设是第 3 代（hw_ver3，与 P4/H4 相同）。硬件里有三样东西：
  - **raw / smooth**：原始计数，以及经过 IIR 平滑后的计数。
  - **benchmark（基线）**：硬件估计的“没碰时的计数”，用一个慢滤波器跟随 smooth。
  - **active threshold**：`smooth - benchmark` 超过它就认为被触摸，同时**冻结 benchmark**，
    免得手指按久了被当成新的基线。
- 关键参数：充放电次数（charge times）决定一次测量数多久，也就决定计数的量级；
  计数寄存器只有 16 位，最大 65535。
- 通道映射（`touch_sensor_channel.h`）：通道 n = GPIO(6 + n)。交互板左槽 KEY_L/KEY_R =
  GPIO13/12 = ch7/ch6，右槽 = GPIO11/10 = ch5/ch4。
- 参考：[IDF 电容触摸文档（ESP32-S31）](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s31/api-reference/peripherals/cap_touch_sens.html)、
  [S31 touch_sensor_ll.h](https://raw.githubusercontent.com/espressif/esp-idf/master/components/esp_hal_touch_sens/esp32s31/include/hal/touch_sensor_ll.h)、
  [hw_ver3 驱动](https://raw.githubusercontent.com/espressif/esp-idf/master/components/esp_driver_touch_sens/hw_ver3/touch_version_specific.c)、
  [IDF 触摸示例默认参数](https://raw.githubusercontent.com/espressif/esp-idf/master/examples/peripherals/touch_sensor/touch_sens_examples_common/touch_sens_example_config.h)。

## 2. 调查：先确认有没有轮子

1. esp-hal 元数据 `esp-metadata/devices/esp32s31/soc.toml` 把 touch 标为 `not_supported`，
   也不导出 `LP_TOUCH` 外设 → 必须自己写寄存器驱动。
2. esp-hal 用的 PAC（`esp32s31`，esp-pacs `5cd68d2`）里有完整寄存器块：
   `LP_TOUCH`（数据与状态）、`LP_TOUCH_AON`（配置）、`PMU.touch_pwr_ctrl`（定时器）、
   `LP_PERICLKRST.touch_ctrl`（时钟与复位）。在工作区直接依赖同一个 PAC 版本，Cargo 会复用，
   不会多出第二份。
3. 官方 BSP（`mosaico_module_interact.c`）给了两条重要信息：KEY 引脚直接映射到触摸通道；
   先尝试触摸模式，失败再退回 GPIO 按键（上拉、低有效）。
4. IDF 的 hw_ver3 驱动给了**初始化顺序**和**默认参数**。驱动按这个顺序移植，每一段用注释
   标出对应的 IDF 函数名（如 `// touch_sensor_enable`），出问题时可以逐段对照。

初始化顺序（`touch_sens::start`）：

```text
开时钟 + 复位 → 上电等待/测量间隔 → 采样配置 0（分频、充放电次数、RC 滤波、驱动强度、偏置）
→ 基线/平滑滤波器 → 各通道阈值 + 清基线 → 打开扫描通道 → FSM 定时器模式
→ force_done 脉冲（≥ 1 个慢时钟）→ 开定时器，连续扫描
```

引脚：触摸需要焊盘浮空、关闭输入缓冲、无上下拉（等价于 IDF 的 `gpio_config_as_analog`）。
`InteractionPort` 空闲时恰好就是这个状态，所以触摸模式下 KEY 引脚什么都不用改。

## 3. 三轮真机调试

第一版就打印了每个键的 `读数/基线` 和是否按住（每 5 s 一行 + 每次变化一行）。
下面三轮都是看日志定位的，没有靠猜。

### 第 1 轮：两个键一直“按住”

```text
touch L 36284/2501 R 37077/10569 held=[true, true]
```

- 现象：读数约 36000，硬件基线只有 2501 / 10569，而且之后一直不变。
- 原因：清基线后，硬件基线从很小的值慢慢爬升；0.5 s 热身结束时还远没收敛。我按这时的
  基线设了硬件阈值，`smooth - benchmark` 远超阈值 → 硬件判定“被触摸” → **基线冻结**。
  死锁：基线不涨，就永远是“按住”。
- 修复：不用硬件基线，软件自己维护（热身后的第一个读数作为基线，之后慢慢跟随）；
  硬件阈值保持最大值，硬件只负责测量和平滑。

### 第 2 轮：按下时读数反而变小

```text
touch L 48628/36191 ... held=[true, false]
touch L 32398/35242 ...
touch L 10834/10347 ... held=[true, false]
touch L 6504/28937  ...
```

- 现象：手指放上去，有时读数冲到 48000，有时掉到 4000–17000。
- 原因：**16 位计数溢出**。空闲已经约 36000，手指让真实计数超过 65535，寄存器绕回。
  例：6504 实际是 72040 − 65536。
- 第二个问题：右键空闲噪声约 ±2.4%，比 2% 的按下门槛还大。
- 修复：充放电次数从 IDF 示例的 500 降到 200，空闲降到约 14500 / 15000；门槛提到
  按下 10%、松开 5%。

### 第 3 轮：手指造成双向摆动

```text
touch L 20529/14487 held=[true, ...]
touch L 6197/12414  held=[false, ...]
touch L 35311/12414 held=[true, ...]
touch L 2148/9848   held=[false, ...]
```

- 现象：不再溢出（最大 35311 < 65535），但按住时读数在 2000–35000 之间来回跳。
- 原因：手指带来的是**双向剧烈摆动**，不是“只升高”。（推测是人体耦合进来的工频等干扰，
  25 Hz 采样看到的是混叠后的结果；没有用示波器验证。）只判断升高的话，摆到低处就“松开”；再加上我让基线快速向下跟随，
  基线被拖到 5000 左右，键又卡在按住。
- 修复：
  - 偏离基线超过 ±10%（任一方向）就算按下；
  - 连续 4 个样本（约 160 ms）都回到 5% 以内才算松开，摆动途中经过基线不会断开；
  - 没按时基线向两个方向都只慢慢跟随（每样本 1/32），按住时冻结；
  - 连续按住 20 s 视为基线失效，用当前读数重新校准。
- 结果：左右键点按都干净地按下 / 松开，KEY_L → Happy，KEY_R → Puzzled，连按 → Angry。

## 4. 可以带走的经验

### 先看信号，再设计判定
- 传感器第一版就要输出原始数据，阈值和算法都留到看过真实数据之后。
- 我两次预设了信号的样子（“基线会很快收敛”、“手指只会让读数升高”），两次都错。

### 数值“反方向”、离谱地跳，先怀疑溢出
- 先查寄存器位宽，再看量级离上限有多远。
- 解决办法是降低量程，留出余量，而不是事后去“补偿绕回”。

### 阈值 = 噪声和信号之间的位置
- 先量噪声（空闲 ±2.4%）和信号（手指 > 20%），门槛放在中间（10%）。
- 按下和松开用两个门槛（迟滞），手指停在边缘时不会抖动。
- 松开要求“持续安静 N 个样本”，可以挡住单个样本的毛刺。

### 别把关键状态交给不透明的硬件逻辑
- 硬件基线有自己的收敛速度和冻结规则，与软件阈值组合后可能死锁。
- 软件维护的状态可预测，还能写成纯函数做 host 测试。

### 纯逻辑与硬件分离，每个真机问题补一条测试
- `touch_key.rs` 不依赖硬件，`scripts/test-drivers.sh` 用 `rustc --test` 直接跑。
- 真机发现的现象都变成了测试：读数下降也算按下、摆动经过基线不松开、按住时基线冻结、
  按太久重新校准等。之后再改也不会退回去。

### 永远留兜底
- 读数不合理 → 退回 GPIO 按键；按住太久 → 自动重新校准。
- 算法出错时设备也不会一直卡在某个状态。

## 5. 工具链与流程上的教训

- **提交前先看状态**：这次设备上有命令被重复执行，一次在 `Cargo.toml` 里重复写了一行，
  一次把最新提交回退掉了。编译、提交、刷机前先看 `git status`、`git log`；
  丢了提交就用 `git reflog` 找回（`git merge --ff-only <hash>`）。
- **命令用 `&&` 串起来**：一次用 `;` 连接，测试失败了提交照样执行，只好 `--amend` 修正。
- **每次刷机用新的日志文件名**，避免读到上一次留下的 `EXIT`。
- **刷机只写 main_app `0x210000`**，不碰 bootloader、分区表和 `0x20000`。

## 6. 下次接新传感器的检查清单

1. esp-hal / 元数据里是否支持？不支持就找 PAC 寄存器块。
2. 找官方 BSP 和 IDF 驱动：初始化顺序、默认参数、引脚和通道映射。
3. 第一版：原始数据日志（周期 + 变化时），保守阈值，加 GPIO 或其他兜底。
4. 真机采集：空闲噪声、操作时的信号范围，确认离位宽上限有多远。
5. 根据数据定门槛和迟滞，判定逻辑写成纯函数并补 host 测试。
6. 加自愈：卡住时自动重新校准、读数异常时退回兜底。
7. 稳定后把周期日志调稀（这里从 5 s 改成 60 s），状态变化日志保留。

## 7. 快速双击不能重复过滤已稳定的状态

2026-10-23 的 N1 Lua 按键验收中，交互板双击窗口放宽至 400 ms 后，惯常快速双击
仍会合并。逐样本日志确认：右键连续五个 smooth 读数已回到基线 5% 以内，TouchKey
在第四个样本报告松开；后级三样本 Debounce 却只收到两次 false，第二次按下就重置了
候选状态，Lua 因而收不到第一次 up。左键也有同一轨迹。证据为
`24-fast-keys-trace.log`，详见 [现场记录](../N1_HAPTIC_LIVE_20261023.md)。

修复在 Touch 模式直接接受 TouchKey 已过滤状态并生成边沿，GPIO 降级仍使用三样本
去抖。四样本 quiet、双向偏差、按住冻结基线和卡死恢复继续由 TouchKey 处理。
三段实测 smooth 序列的主机回放均得到 down/up/down/up，旧路径负对照只产生一次
down。设备复测有左键 8 次、右键 4 次双击及左右完整约 2 秒长按，操作者认可手感。

这次问题来自过滤阶段组合，不是电容充放电速度的实测结论。仅三个 quiet 样本的间隔
仍受四样本防噪规则约束；诊断 UART 也会影响调度，所以使用相邻真实时间戳，不以
整份日志中的未采集区间推断任务冻结。输入链路应明确区分原始读数、过滤后的状态与
已经确认的边沿，避免每一层都重复等待稳定。
