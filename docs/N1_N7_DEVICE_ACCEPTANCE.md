设备最后运行的是 N1 首次烧录镜像。后续阶段的本地构建尚未烧录。
先在旧分区布局验收 N1/N2/N3/N7/N4/N5，再备份并单独验收 N6 分区迁移和 OTA。
每次测试记录：集成提交、BIN SHA-256、启动日志、供电方式、插板位置、实际结果。
N1 已保存的默认与诊断镜像指纹、烧录地址和恢复步骤见 [N1 清单](N1_TEST_CHECKLIST.md)。

最新集成默认镜像为 `target/n6-acceptance-20261023/n6-default.bin`，完整指纹和构建收据见
[N6 收据](N6_USB_OTA.md#2026-10-23-independent-acceptance-receipt)。它同时支持严格识别的旧布局
和新布局；先在旧布局验证普通功能。N1–N5/N7 历史快照仅用于代码审查和旧布局复现，

## N6 A/B 与 USB OTA

实际分区重写遵循 [HANDOFF.md 红线](HANDOFF.md#红线)，使用 [迁移与恢复命令](N6_MIGRATION.md)：
工具保存完整 16 MiB 原始备份，并独立重读 `0x0..0x20000`，将设备 MAC、表、镜像和哈希绑定
到离线 plan。审查具体 plan 后，在明确授权的现场步骤中执行。完成主机检查不代表已迁移。

- [ ] 完成完整备份与 boot region 独立重读，记录大小、SHA-256、设备 MAC 和恢复命令；备份放仓库外。

- [ ] 审查 plan 后现场执行迁移，保留写后 full Flash 对比收据；故障注入镜像不用于首次迁移。
- [ ] 迁移后新 data 正常挂载；vibe_mode 仍能启动；bootloader / vibe_mode / ui_apps / system 字节保持一致。
- [ ] 初次空 metadata 只能在双挂载、首帧、VM 与连续 30 秒健康窗口后建立 slot 0 Valid；自检前拒绝 begin。
- [ ] USB OTA 写入非运行槽，ACK 到达后重启；两槽诊断显示版本 / 状态，实际槽位改变，自检后为 Valid。

- [ ] 未确认 New / PendingVerify 候选拒绝另一次 begin，不能覆盖回退槽。
- [ ] ACK 丢失或三秒发送超时不记作成功启动；重新查询两槽状态，确认已选候选和实际运行槽，必要时人工重启。
