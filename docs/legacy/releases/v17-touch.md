# v17-touch：修正 GT1151 触摸报文

触摸控制器能返回产品 ID `1158`，但点击没有效果。代码对照发现，应用将 GT1151 报文按 GT911 的状态位和错误的记录起点处理。当前修正依据同事项目的 `src/touch.rs`，并由原 C 项目中的 `espressif__esp_lcd_touch_gt1151` 组件核对。

## 协议差异

| 项目 | 原驱动 | GT1151 参考实现及本版 |
| --- | --- | --- |
| 触点判断 | bit7 未置位立即返回 Up | 使用状态低四位触点数，不要求 bit7 |
| 首记录起点 | 从 `0x8150` 读取并当作 track 字节 | 首记录在 `0x814F`，X 为 `0x8150/51`，Y 为 `0x8152/53` |
| 报文长度 | 只读首点 8 字节 | 状态 1 字节 + 每点 8 字节 + 按键 1 字节 + 校验和 1 字节 |
| 校验 | 无 | 完整报文字节累加模 256 等于 0 |
| I2C | 400kHz | 对齐参考实现的 100kHz |

状态值 `0x01` 表示一个触点，旧逻辑会将其当作无触摸并提前返回，状态也没有被清除。即使读到 bit7=1 的报文，记录起点偏移仍会把 X 高字节、Y 低字节等拼成错误坐标，造成按钮无法命中。

这两项是代码层面确认的协议错误；尚无该版本的真机日志证明各项对同事设备的实际影响比例。100kHz 是与参考配置对齐，没有独立证据证明原来的 400kHz 导致此次失效。GPIO 仍为 SDA=0、SCL=1，esp-hal 已配置内部上拉。

## 修正内容

- 读取 GT1151 完整产品信息及触摸报文，校验后返回首个触点坐标；支持读取最多 10 个触点以覆盖整包校验。
- 数据读取成功后清除状态；I2C 错误、校验失败、截断、触点数变化及越界坐标作为错误记录，避免把坏数据当作抬手而产生误点击。
- 向 Slint 先提交指针位置，再提交按下事件；零触点报告提交抬起事件。
- 保留按下/抬起、档位切换和累计触摸诊断。高频轮询只更新计数，主循环心跳汇总错误。
- 保留显示驱动中的 `OUT_EOF_MODE=0`、时序和 DMA 补块/发布协议，应用继续使用 Rust / esp-hal。

## 验证与日志

`./scripts/test-touch.sh` 检查按协议构造的固定报文字节，包括 bit7=0 的有效触点、正确坐标偏移、完整 16 位小端解析、屏幕角点、多触点校验、坏校验、截断及非法触点数。主固件进行 release 交叉编译，版本包校验镜像和分区边界。这些检查不替代硬件验收，包内 `hardware_verified` 为 false。

烧录后，启动日志应包含 `v17-touch` 和 `GT1151 触摸已就绪 (I2C=100kHz, GT1151 完整报文校验)`。依次点击 0、25、50、75、100、AUTO，并在屏幕四角按下及释放：

- 有效点击应出现 `触摸按下`、`触摸抬起`，档位按钮应另有 `UI 档位切换`；坐标应与按下位置一致。
- `触摸累计` 的有效按下报告数应随触摸增加。I2C、校验、无效报文和越界计数用于定位输入中断的位置；`最近按下状态` 保留最近有效触点报文的状态，即使当前已抬手。
- 屏幕应继续稳定输出，显示心跳的 EOF 失步和 DMA 错误不应持续增长。

如仍有失效，所需证据为本版完整启动日志、按住一个档位约 1 秒后抬手的事件日志，以及随后一条触摸累计统计。
