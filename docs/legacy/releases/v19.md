# v19：触摸响应与静态红边诊断

适用硬件：ESP32-S31-Korvo-1 + SUB3 800×480 RGB LCD、GT1151 触摸。

## 触摸响应

旧版使用 `RepaintBufferType::NewBuffer`，每次重绘整个 800×480 界面，随后在 `flush()` 内忙等换帧。触摸只能在这些步骤结束后再次采样；旧版硬件记录中的全帧渲染约为 160ms。档位相关的转速、百分比和功率还要等待下一次 1 秒模拟数据更新。115200 波特率下的长心跳日志也占用主循环。

本版使用 Slint 的 `SwappedBuffers`，重绘两块交替缓冲最近两帧的脏区。`present()` 提交后立即返回，等待 ISR 接收期间继续处理输入。发布完成前不修改任何帧缓冲；超时撤回后重建两块缓冲的脏区历史，避免把未交换的缓冲当作已交换。

档位数值和 PWM 目标在输入事件所在轮更新。默认心跳改为每 2 秒一条简短摘要，长按期间延后。完整 LCD/DMA 统计及触摸报告计数改为 debug 级别。心跳新增自开机以来的最长触摸采样间隔和单次读取耗时；这些累计最大值包含开机首帧等慢帧，不能直接当作稳定运行时的平均延迟。

局部重绘仍同步执行，首帧、启动页交接和曲线更新仍可能延长一次采样间隔。实际响应改善幅度需要新固件的真机测量。

## 静态文字红边

当前内嵌字体为单通道灰度字形。主机测试使用同一套内嵌字体，黑白中英文探针的 2,319 个抗锯齿像素均无红蓝通道偏差；导出的 RGB565 主界面未复现红边。该结果只验证软件输出，无法排除目标机、GPIO 电气时序或面板问题。

保留已验证的 RGB565 引脚顺序、18MHz PCLK、下降沿和 `OUT_EOF_MODE=0`。启动日志增加 `LCD 像素读回`，预期：

```text
byte_mode=1 byte_swap=false bit_reverse=false swizzle=false convert=false data_delay=0x00000000
```

构建独立诊断版本：

```bash
cargo firmware --locked --features lcd-color-test
```

上电先显示 15 秒原始 RGB565 图案，再进入控制界面。图案从上到下依次是黑白/RGB/CMY 彩条、32 级灰阶、1px 竖条、1px 横条、8px 棋盘，以及白底 2px 黑线；不经过字体、透明度混合或 Slint 渲染。测试期间仍轮询触摸并推进风扇斜坡。

- 灰阶或底部黑线也有明显红边：继续检查 RGB 数据、采样边沿、连线和面板；记录彩条颜色及红边方向。
- 图案正常而 UI 文字异常：对照 UI 的 RGB565 软件图与实屏近照，继续定位目标机渲染或输出差异。
- 单像素条纹可能呈现面板子像素纹理，应结合灰阶和底部宽间距黑线判断。

当前尚未取得新版本的真机彩条、近照或日志，红边根因未确认。

## 验证

`./scripts/check.sh` 检查核心、启动时序、GT1151 报文、桌面模拟器、两种桌面布局、MCU release 构建与固件依赖隔离。新增 RGB565 回归测试逐像素比较局部重绘与完整重绘，覆盖启动页交接、档位与仪表变化、曲线更新，以及发布失败后在同一缓冲重试。

普通固件与 `lcd-color-test` 固件均进行 release 交叉编译。所有软件验证通过仍不代表真机验收完成，`hardware_verified` 保持为 `false`。

上板后依次点击 0/25/50/75/100/AUTO，检查选中状态与仪表同轮更新、连续点按及长按正常，`EOF失步`、`欠载`、`DMA错误` 不持续增长。默认日志保留按下、抬起、档位事件和简短心跳；需要详细诊断时以 `ESP_LOG=debug` 重新构建。
