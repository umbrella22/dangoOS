dangoOS v0.6.1 修复团子拖动和转动设备时的横向错层。发布默认值继续为 RGB565、40 MHz QSPI、正常 TE、450 KiB PSRAM PARTIAL 绘制缓冲与 Rust 团子行为；默认 Lua 前台应用引擎保留，显示计量和 EmbedScope 诊断关闭。

## 修复显示传输

旧路径直接从 PSRAM 向 SPI DMA 供给像素。设备计量发现，部分 32,640 字节窗口只经过几百微秒就被 HAL 返回为成功，同时 SPI 的发送 AFIFO 读空错误已经置位。传输错误未被驱动检查，可能使屏幕混入未被完整覆盖的旧像素。

像素现在先复制或编码到两块各 16 KiB、128 字节对齐的片内暂存，再由 DMA 上传。当前块上传与下一块准备仍然重叠，源帧租约持续保留至本次上传结束。RGB565 / RGB888 全屏分别使用 30 / 48 个合法的两行窗口。

驱动检查发送 FIFO 错误，异常窗口返回失败；未完成帧不会被确认成功。此修复不提高 QSPI 频率，也不改变 TE 等待、角色尺寸或转向动作。

## 性能与验证口径

修复计量候选记录的 13,548 个 Home 更新均无 FIFO 错误；最长连续采样段的软件上传完成率约为 22.55 FPS。人工拖动、慢转、快翻、设置滚动和返回后确认画面正常，无撕裂或残留。该结果对应修复计量候选，发布构建关闭诊断，两者分别核对镜像身份和验收。

v0.6.0 中 12.45 → 24.33 FPS 的历史对照未检查 FIFO 错误，不能证明完整像素帧提高约 95%。先前独立观测到的 UI 循环耗时下降仍保留；修复后的 Lua / Rust 同条件传输对照尚未重做。22.55 FPS 也是软件完成率，不能代替光学帧率或认定稳定 30 FPS；实际 SCLK 和脉宽未做电气测量。

板级分块回归同时覆盖最大 DMA 容量和当前 16 KiB 暂存，检查两种颜色格式的完整行覆盖、边界及窗口对齐。发布流水线重新执行完整主机检查、Lua / TS 前台引擎构建与符号隔离、Recovery 构建、资源预算和发布包校验。主机检查、串口健康与人工画面观察分别记录。

## 安装与资源

沿用 v0.5.0 的 `S31ONE03`：独立 Recovery 与单个 12 MiB 主应用分区。

- 已采用该布局的设备可使用 `main` 包更新主应用；更新保留用户数据。配套资源与 USB 工具随 ZIP 提供。
- v0.4.4 及更早的 A/B 布局必须使用 `full` 包迁移，不能用旧 OTA 或本版 `main.bin` 改变布局。
- `full` 包覆盖 NOR 系统及配置；独立 NAND 不在 NOR 写入范围。只有显式传入 `--format-nand` 才会初始化 NAND。
- 本次实体安装验证范围为主应用，未对最终 full 包执行设备全量重装；使用前核对包内 `INSTALL.md`、`manifest.json` 和 `SHA256SUMS`。
