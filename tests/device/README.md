# 设备验收探针

探针用于检查固定硬件行为，manifest ID 与当前目录名一致，Lua 日志标记沿用既定
含义。它们只依赖固件提供的 `delay`、`imu`、`magnetometer`、`fuel_gauge` /
`lib_fuel_gauge`、`haptic`、`led_strip` 和 `button`，不需要额外应用文件或第三方
Lua 依赖。

| 应用 ID / 目录 | 固定行为 | 预期结果 |
| --- | --- | --- |
| `contract` | 传感器快照与范围检查、校准写回后恢复原值、电量模块别名、两次短马达请求、LED 像素 0 暗红/像素 5 暗绿，以及标称 60 s 窗口内的有效按键回调（参数最多允许 120 s），最后清理。 | `[N1] SUMMARY` 中 FAIL 为零；硬件不可用或未观察到手势时可产生 SKIP。实际灯光、震动及输出时序仍需观察。 |
| `lifecycle` | 标称 90 s 窗口（最多 120 s）：右板 GPIO11/10 手势，单击时最多十次 `error` 马达请求；拔出/重插后检查旧句柄仍无效，再重新打开按键和两个绿色 LED 端点；正常结束时清理。 | 按规定完成实体操作后，`[N1L]` 生命周期序列为 PASS；未做实体操作只能记录 SKIP，不能算实物验收通过。 |
| `errors` | 与 lifecycle 使用相同 Lua，启动清单固定 `mode="error"`：显示红/绿端点 3 s，然后抛出 `N1_EXPECTED_FAILURE`，不显式清理。 | 预期出现运行器错误、VM 销毁和 LED 使用权释放；随后运行正常 lifecycle 探针验证可重新打开。该错误是预期刺激，不是正常成功退出。 |
| `haptic` | 等待 5 s 后发送四次 `angry` 请求，间隔 3 s；预设为两段 160 ms、90% 占空比。 | `[N1H] END` 只表示请求完成；需独立触摸感受马达。寄存器记录需要诊断固件。 |

`haptic-rate` 提供有限请求刺激，供逻辑分析仪验证“波形启动间隔至少 150 ms”的限速规则。
它先等 5 s，再以标称 40 ms 间隔发送 20 次 `thinking`，最后等 1 s 处理待完成工作。
固件预设为单段 30 ms、35% 占空比，只依赖 `delay`、`haptic`。请求日志不是实际波形
开始时间，请求可能合并，脚本结束也不能证明物理时序。需要单独测量实际马达波形的
启动间距；探针不读取 GPIO 或寄存器，没有无限循环。

从仓库根目录运行有限时长的控制台会话，日志路径必须是**新路径**：

```sh
python3 scripts/device/session.py --log target/n1-contract-new.log \
  --wait 60 --seconds 90 --command status --push tests/device/apps/contract
```

`--command` 可以重复，按顺序在 `--push` 之前执行；上传后总会运行应用。
`--port` 覆盖运行时默认端口 `/dev/cu.usbmodemmosaico_s31_r11`。
`--wait` 限制连接重试时长，`--seconds` 限制最后的日志采集窗口，两者都接受有限、
非负秒数。每次串口写入超时为 20 s，协议回复沿用推送工具的 20/30 s 超时。
等待时长为零时只连接一次，日志窗口为零时不继续跟随日志。

脚本导入相邻 `console.py`，复用协议且不写入字节码缓存。`--help` 不需要 pyserial，
实际会话需要安装它。日志包含 UTC 开始、连接、结束标记及错误，拒绝覆盖已有路径。

退出码 0 只表示传输会话完成，不会解析 Lua PASS/FAIL、认证预期异常后的清理，
也不代表实物验收。退出码 1 表示配置/协议失败，2 表示串口、I/O 或命令行失败，
130 表示中断。缺少回执、显式 `@err` 和检测到的串口断开均视为失败。
这个会话工具不提供烧录功能。
